2. Abstract

Outpatient appointment no-shows represent a pervasive and costly operational problem in modern healthcare management, leaving clinical personnel idle, lengthening waiting lists, and delaying patient treatment. Conventional clinic administration approaches either rely on uniform, undifferentiated SMS reminders or unsystematic front-desk follow-up calls. This project presents ClinicFlow, a desktop-grade clinical appointment and smart queue management system engineered in Java 17 that natively integrates an embedded Machine Learning engine using Weka 3.8.6. The predictive model is trained and rigorously evaluated on the genuine, public Medical Appointment No-Shows dataset comprising 110,527 historical records from the public healthcare network (SUS) of Vitória, Brazil.

To prevent temporal data leakage, an 80:20 chronological train/test split was instituted, yielding 88,417 training instances and 22,104 untouched test instances. A Class-Balanced Random Forest classifier (100 decision trees) was selected following empirical benchmarking against a naive ZeroR majority-class baseline. On the held-out test partition, the model achieves an overall accuracy of 77.50%, a no-show recall of 32.93% (successfully detecting 867 missed appointments that a naive baseline misses entirely), a precision of 21.28%, an F1-score of 0.2585, and an area under the ROC curve (ROC-AUC) of 0.6658.

The system features a multi-threaded Java Swing user interface powered by SwingWorker for non-blocking model loading, atomic CSV persistence, an advisory risk-tiering system (Low, Medium, High) recommending proportional reminder actions (automated SMS, enhanced SMS, phone outreach), and a fair First-In, First-Out (FIFO) queue management engine where ML risk is strictly non-punitive. Crucial clinical limitations, including Brazilian-to-Indian healthcare domain shift and observation right-censoring, are systematically audited and documented.

3. Introduction

Efficient outpatient appointment scheduling is the foundational operational bridge between patient demand and medical provider capacity. Missed consultations ("no-shows") occur when patients fail to attend pre-scheduled visits without notifying the facility in advance. This absenteeism leaves expensive clinical examination rooms and physician time completely unutilized while other patients experience extended waiting times.

Traditional appointment management relies on static reminders that treat all appointments identically. However, patient attendance behavior is multifactorial, depending heavily on scheduling lead time, patient age, chronic illnesses, and booking circumstances. By incorporating predictive Machine Learning directly into the Java-based appointment booking workflow, front-desk staff can obtain real-time, data-driven decision support to prioritize high-risk appointments for proactive outreach.

4. Problem Statement

Outpatient healthcare facilities experience substantial capacity waste and revenue loss due to unannounced patient appointment no-shows. Clinic receptionists lack quantitative, automated tools at the time of appointment registration to distinguish between reliable bookings and those with a high likelihood of absence. Without risk-stratified guidance, clinics cannot target their limited administrative follow-up resources effectively, resulting in preventable slot abandonment, prolonged community waiting queues, and poor patient health outcomes.

7. Proposed System: ClinicFlow

ClinicFlow unifies clinical appointment operations and predictive data science into a single, cohesive Java 17 desktop software suite. By embedding Weka 3.8.6 directly within the application JVM, the system evaluates ML inference vectors synchronously upon appointment booking.

Core Ethical Operating Principle: Machine Learning predictions within ClinicFlow are strictly advisory. Predictions serve exclusively to guide staff in proactive reminder communications (e.g., placing a courtesy phone call to high-risk bookings). Model predictions never cancel appointments, alter physician availability, or affect patient queue sequencing in the waiting room.

8. Dataset Description

The system is trained and evaluated using the genuine, publicly verified Medical Appointment No-Shows dataset:

  • Kaggle Attribution: Joni Hoppen, Medical Appointment No Shows.
  • Public Source: Kaggle / Verified Public GitHub Mirror.
  • Healthcare Origin: Municipal public healthcare system (SUS) of Vitória, Espírito Santo, Brazil.
  • Collection Window: Appointments scheduled between April 29, 2016 and June 8, 2016.
  • Original Raw Records: 110,527 rows across 14 columns.
  • Class Ratio: 88,208 Attended (79.81%) vs. 22,319 Missed (20.19%) — an approximate 4:1 class imbalance.

9. Data Preprocessing & Anomaly Pruning

Raw CSV data was parsed and validated using Apache Commons CSV in DataPreprocessor.java. The original file (data/raw/appointments.csv) is preserved untouched. Exactly 6 anomaly records (0.0054%) were identified and pruned:

  • 5 Negative Lead-Time Records: Appointments where the scheduled consultation date preceded the registration date (e.g., scheduled on May 10 for May 09). Chronologically invalid.
  • 1 Biologically Impossible Age Record: Exactly one record had an age of -1.

The remaining 110,521 valid records were exported to data/processed/clean_appointments.csv with zero synthetic imputation.

10. Machine Learning Algorithm Selection

Random Forest Classification was selected for its proven efficacy on heterogeneous tabular healthcare data. The algorithm constructs an ensemble of 100 de-correlated decision trees using Bootstrap Aggregation (Bagging) and random feature subspace sampling. Individual trees output class probability distributions, and the ensemble computes the arithmetic mean probability via soft voting: 

p(No-Show | x) = (1 / 100) * Σ p_tree(No-Show | x)

To counteract the 4:1 class imbalance, Weka's FilteredClassifier was paired with ClassBalancer, weighting training instances inversely proportional to their class frequency to ensure strong no-show sensitivity.

Critical Leakage Audit: Primary keys (PatientId, AppointmentID) were excluded to prevent memorization. Most importantly, SMS_received was strictly excluded from booking-time inference because SMS reminders are dispatched days after the appointment is booked. Using it at booking time would constitute severe temporal data leakage.

12. Training & Testing Methodology

The dataset was sorted strictly chronologically by ScheduledDay to model authentic real-world deployment:

  • Training Partition (Earliest 80%): 88,417 records (Nov 2015 to May 25, 2016 08:47:31).
  • Testing Partition (Latest 20%): 22,104 records (May 25, 2016 08:47:32 to June 08, 2016).

Right-Censoring Investigation: The test set exhibits a lower no-show rate (11.91%) than the training set (22.26%). An audit revealed that this is an observational right-censoring artifact of the 40-day Kaggle collection window: because data collection ended June 8, patients booking after May 25 with lead times > 14 days were cut off. This caused same-day bookings (which have very low no-show rates) to jump from 28.8% in training to 59.1% in testing, mathematically lowering the test set no-show rate.

14. System Architecture

ClinicFlow is organized into a clean 5-tier Object-Oriented architecture:

  1. Presentation Layer: Java Swing UI components (ClinicFlowApp, DashboardPanel, AppointmentBookingDialog, QueueManagementPanel, etc.).
  2. Service Layer: Coordinates clinical operations (AppointmentService, PatientService, DoctorService, ReminderService, WekaNoShowPredictionService).
  3. Domain Model: Rich OOP entities (Person, Patient, Doctor, Appointment, PredictionResult, ReminderRecord).
  4. Repository Layer: Decoupled repository interfaces implemented with thread-safe atomic CSV file swapping (CsvPatientRepository, CsvAppointmentRepository).
  5. ML Engine: Embedded Weka 3.8.6 pipeline (DataPreprocessor, FeatureExtractor, NoShowPredictor, ModelRepository).

16. Machine Learning and Java Integration

The complete Machine Learning lifecycle runs natively within the JVM. Historical training records are ingested via Java CSV parsers, filtered via Weka Java APIs, serialized using Weka's native SerializationHelper, and deserialized into memory at application boot. At booking time, Appointment entities are mapped to Weka DenseInstance objects and evaluated in sub-millisecond time.

20. Practical Limitations

  • Domain Shift: Model trained on 2016 Brazilian SUS public clinics; attendance dynamics in Indian private healthcare will differ.
  • Dataset Right-Censoring: Fixed 40-day collection window truncates test set lead times.
  • Uncalibrated Probabilities: Soft voting percentages approximate but do not represent formally calibrated probabilities.
  • Moderate Precision: A 21.28% precision means reminder phone calls must be conducted as polite courtesy inquiries.
  • Simulated Communications: SMS and telephony are simulated locally and logged to CSV rather than using paid external gateways.
  • Storage Concurrency: CSV storage is optimized for single-clinic reception desks rather than multi-hospital networks.
